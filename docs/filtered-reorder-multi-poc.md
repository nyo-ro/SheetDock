## 検索中の境界規則

参照した現在の実装：`Sheaside/Services/WorksheetMoveRules.cs`の`GroupOrder`、`BoundaryAt`。既存TypeScriptの`src/domain/movePlan.ts`の`groupOrder`はこの規則と一致している。

- 先頭境界：最初の表示シートの直前。
- 途中境界：次の表示シートの直前。対象外シートが前の表示シートとの間にあれば、その対象外シートの後ろになる。
- 末尾境界：最後の表示シートの直後。ブック全体の末尾ではない。
- 対象を元の位置から除いて挿入し、移動対象以外のシートの相対順序は維持する。
- 元位置の周辺へのドロップでも、対象外シートをまたぐなら実際の順序は変わる。全体の最終順序が同じ場合だけ書き込まない。

例：全体 `外A → 対象1 → 外B → 対象2 → 外C`、検索文字列 `対象`。

| 操作 | 全体の期待順序 |
|---|---|
| 対象2を検索先頭へ | 外A → 対象2 → 対象1 → 外B → 外C |
| 対象1を対象2の直前（表示行間）へ | 外A → 外B → 対象1 → 対象2 → 外C |
| 対象1を検索末尾へ | 外A → 外B → 対象2 → 対象1 → 外C |
| 対象1を検索先頭へ | 変更なし |
| 対象2を検索末尾へ | 変更なし |

ドラッグ開始時に全体スナップショット・表示ID列・検索文字列を固定する。挿入線は表示一覧の境界、APIへ渡す境界は元の全体一覧で計算する。検索条件・表示対象・ブック世代の変化でドラッグを破棄。ドロップ後は既存の移動処理で全体を再取得・照合してから1回だけpositionを書き込む。検索文字列は移動後も維持する。

既存の読み取り専用・構成保護・対象保護・対象消失・名前/順序/状態変化・総シート数不明/不一致・アクティブ種類不明の拒否を維持。失敗時は再取得し、変更が適用された可能性を含めて表示する。

## 複数移動PoCの範囲と安全性

通常UIの複数選択は追加していない。開発専用PoCの既存`groupOrder`、`positionPlan`、`runExperiment`、React確認ダイアログを再利用。

- 対象を名前のチェックボックスで選び、移動先を「名前の前」または「末尾」で指定可能。内部ID/JSONの手動編集は不要。従来のID/境界番号入力も詳細検証用に残す。
- クリックした順番ではなく、元のブック順で対象の相対順序を維持。非対象の相対順序も維持。
- 連続/非連続対象、先頭/途中/末尾、自分自身を含む境界、同位置に対応。非連続の選択は最終的に連続したグループになる。
- 既存計画は対象だけをいったん末尾へ集め、最終位置へ動かす場合がある。途中順序と複数のposition書き込みを明示する。原子的トランザクションではない。
- 検証ブックの明示的有効化、通常シートのみの自己確認、完全一致のブック名、固定計画と明示確認を維持。
- 移動計画では、引数なし`workbook.functions.sheets()`の総数と取得したWorksheet件数の一致を各書き込み前後で必須にした。自己確認だけでは混在を許可しない。取得不可/エラー/不正値はnullとして拒否。同位置の計画でも検証する。
- 保護/読み取り専用/状態差異は既存処理で拒否。最初の失敗で後続を中断し、再取得する。結果は`success`（確認済み成功）、`failed`（送信前失敗）、`unknown`（送信後・結果不明）、`unprocessed`（未処理）を維持。
- 合成失敗は`SyntheticFailure`と記録し、本物のOffice APIエラーの再現成功とは区別する。自動ロールバックは行わない。

SHEETSによる判定の公式根拠/API Setは[前回文書](worksheet-sync-reorder.md)を参照。今回新しいOffice APIや依存パッケージ、Requirement Setは追加していない。各観測は複数回のsyncであり、原子的な状態取得や完全な共同編集排他を保証しない。

## Excel for the webでの手順

### 起動と通常UI

既存の開発サーバーとサイドロード設定を利用する。開発サーバー停止中ならSheetDockディレクトリで`npm.cmd run dev`。NodeがPATHにない場合は既存の`.local-tools/node-v24.22.1-win-x64`をPATHへ追加する。起動済みなら変更反映後にペインを再読み込みする。manifestを変更していないため、既存の登録が残っていれば再登録は不要。

使い捨ての検証ブックで、Excel標準UIから `外A、対象1、外B、対象2、外C` をこの順に準備する。通常画面で `対象` を検索し、上記表の各操作を試す。**各ケース前にExcel側で元の順序へ戻し、自動同期を確認**する。

各回、挿入線、Excel全体の順序、検索結果の順序、検索文字列が残っていること、アクティブシートが変わらないことを照合。検索中のEsc/一覧外キャンセルも再確認する。ドラッグ中に検索文字列を変更できた場合は古いドロップが実行されないことを確認する。再取得前後の競合を実機再現できなければ未検証と記録する。

### 複数移動PoC

1. 別の使い捨てブックで、通常シート `A → B → C → D → E` を作る。
2. PoCで「観測・再取得」。2つの有効化チェックを確認し、観測値にあるブック名を完全一致で入力。
3. 操作を「単一・複数移動」に変更。下表どおり対象名にチェックし、「移動先を名前で選択」で指定。
4. 「計画を作成」で変更が起きないことを確認。「確認して実行」で名前・書き込みステップ・想定する最終順序を確認。最初はキャンセルし、変更がないことを確認。
5. 再度確認画面を開き、明示的に「実行」。結果の`expectedOrder`/`actualOrder`/`orderMatches`と実際のExcel順序を照合する。ID列の手動編集はしない。
6. 各ケースで元の順序に戻し、再取得・対象選択・計画作成をやり直す。

| ケース | 対象 | 移動先 | 期待する最終順序 |
|---|---|---|---|
| 連続・先頭 | B,C | Aの前 | B,C,A,D,E |
| 非連続・先頭 | B,D | Aの前 | B,D,A,C,E |
| 非連続・途中 | B,E（Eから選んでも同じ） | Dの前 | A,C,B,E,D |
| 非連続・末尾 | B,D | 末尾 | A,C,E,B,D |
| 自分を含む同位置 | B,C | Cの前 | A,B,C,D,E（書込0） |

### 途中失敗・安全性

`A,B,C,D,E`でB,DをAの前にする計画は次の4書き込みになる。

1. Bを末尾へ：A,C,D,E,B
2. Dを末尾へ：A,C,E,B,D
3. Bを先頭へ：B,A,C,E,D
4. Dを2番目へ：B,D,A,C,E

合成失敗番号を2にし、まず「書き込み前」を選ぶ。期待：`success, failed, unprocessed, unprocessed`、実順序は `A,C,D,E,B`。元に戻して再取得し、「書き込み後・確認前」でも試す。期待：`success, unknown, unprocessed, unprocessed`、実順序は `A,C,E,B,D`。`orderMatches`は両方false。結果が違えば記録し、成功扱いしない。

確認ダイアログを開いた後にExcel側で対象名/順序を変更し、実行で中断することを確認。構成保護・読み取り専用・対象シート保護も専用ブックで試す。既存グラフシート混在ブックのコピーでは、一覧に出ないグラフシートを先頭/途中/末尾に置いても変更が拒否されることを別途確認する。自己申告チェックでガードを解除しない。

この手順全体はユーザーによる今回の再検証待ち。Codexは実Excelを操作していない。
