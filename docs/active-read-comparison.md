## 目的と確認済みの範囲

ユーザーの既存ログでは、名前編集を開始してEscで取り消したケースで、名前変更イベントが0回でもactive ID取得の`context.sync()`が約2分40秒以上戻らなかった。一覧基本情報の取得とイベント解除・再登録は完了していた。1件の未完了Promiseが共通キューを待たせる構造は確認済みだが、最初のAPI無応答の直接原因は不明。

今回の比較は、通常UI・PoCの自動同期・共通キューを動かさない専用ページ実行環境で、取得方法を1つずつ変える。Excelへの変更API、イベント登録、総シート数の関数評価、保護状態取得は実験に含めない。`delayForCellEdit`も変更しない。

## 比較するAPI

実装：`src/dev/readProbe/api.ts`。A・B・Cとも、実験本体は`Excel.run`1回と明示的な`context.sync()`1回。`load`やオブジェクト参照は要求をキューへ積み、プロパティ値はsync完了後に読む。以下の回数はSheetDockが開始したrun/syncであり、Office.js内部のHTTP通信数ではない。

| 試験 | 実験本体 | 読み取る値 | Excel API Set | 追加の事前準備 |
|---|---|---|---|---|
| A：一覧のみ | `workbook.worksheets.load("items/id,items/name,items/position")` → sync | 各通常ワークシートのID・名前・位置 | 1.1 | なし |
| B：既知ID | `worksheets.getItemOrNullObject(knownId)` → `load("id,name")` → sync | 存在確認、対象のID・名前 | 1.4 | 同じ新規ページ内で、一覧取得を1回だけ明示実行。準備完了後に画面から対象を選ぶ |
| C：アクティブのみ | `worksheets.getActiveWorksheet()` → `load("id")` → sync | 現在の通常ワークシートのID | 1.1 | なし |

A・Bでは`getActiveWorksheet()`を呼ばない。Bは画面にある候補から選択し、内部IDやJSONを手入力しない。対象が削除されていれば失敗として終了し、別シートへ置き換えない。Bの準備1run/1syncは本試験1run/1syncと分けて記録するため、セッション合計は通常2run/2syncとなる。A/Cは通常1run/1sync。

上記は正式公開API。参照ページのURLに`view=excel-js-preview`が含まれていても、今回のメソッドをPreview APIとして採用した意味ではない。[WorksheetCollection公式リファレンス](https://learn.microsoft.com/en-us/javascript/api/excel/excel.worksheetcollection?view=excel-js-preview)

## 実験の独立性

開発版の通常画面にある比較モード入口から、`sessionStorage`の`sheetdock.readProbe`を`1`にしてページを再読み込みする。次の起動では比較画面だけをマウントし、通常の`App`と既存のPoCを起動しない。比較モードの画面表示だけでA/B/CのExcel APIを実行しない。

- 1つのページ実行環境で実験本体は1回だけ。予約後・成功後・失敗後の再実行やA/B/Cの変更は許可しない。Bの準備は、そのB試験に限った明示的な1回の準備である。
- 新しい試験ではページを再生成し、セッション識別子が前回と異なることを確認する。前回のシートID・名前・Promise・キューは引き継がない。
- 通常UIの共通Excelキューを実験から参照しない。既存キューのロックを解除して再利用する仕組みではない。
- 未応答のAPIがある間は次の試験・通常画面への復帰を開始しない。15秒の警告は未応答の通知であり、API取消しやロック解除ではない。
- 未応答になったら診断JSONを保存し、Excelのブラウザータブ全体を再読み込みする。その後に新セッションで次の試験を開始する。再読み込み前の未完了APIと別APIを並行実行しない。
- ペインの閉じる／開く操作だけでは、実行環境が必ず新しくなるとは扱わない。セッションの変化を確認する。
- 新ページはJavaScript側の状態を分離するが、Excelホスト内部が完全に初期状態へ戻った保証ではない。再読み込み後も基本読取りが停止する場合は、その試行を正常な比較結果として採用しない。

試験中はソースを編集せず、開発サーバーを再起動しない。HMRやページ再読み込みが起きると実行環境とメモリー内ログが変わる。正常終了後は「新しい実行環境へ（再読み込み）」で次の試験へ進み、「通常画面へ（再読み込み）」で通常起動へ戻れる。未応答中はこれらを無効化し、ログ保存後のExcelタブ全体の再読み込みを案内する。予約を取り消した場合も同じ環境で別試験は開始しない。

通常画面を表示するProductionでは、この起動分岐・比較UI・実験コードを含めない。既存PoCも引き続きProductionへ含めない。通常UIのイベント管理・安全判定・ドラッグ移動は変更対象外。

## 診断情報と時刻の意味

画面の診断JSONで、セッション、試験種別、準備／本試験の区別、状態、段階別の開始回数、時刻と経過時間を確認する。`api.run.start/end/error`と`api.sync.start/end/error`から、run開始前・sync待ち・sync後のどこまで進んだかを分ける。終了記録は例外時にも出るので、`end`だけで成功と判断せず、errorと最終状態も照合する。

主なJSON項目は`session`、`kind`、`status`、`pending`、`waitingAt`、`apiCalls.preparation/experiment`、`counts`、`entries`。各行の`time`はUnix時刻（ms）、`isoTime`はUTC、`elapsedMs`は実行環境開始からの単調時計による経過時間、`durationMs`は完了した処理時間。手動記録は`source: "manual"`と`manual.editStart` / `manual.escape`で区別する。API段階は`preparation.api.sync.start` / `experiment.api.sync.start`などの接頭辞付き。診断は直近300行に制限し、総回数は別保持する。

記録対象：

- ページ初期化、実験予約・開始、API要求開始、sync開始・終了、エラー、15秒応答待ち、遅れて完了した場合の状態。
- 実時刻とページ起動からの経過時間。処理時間は単調増加時計を使用し、時刻調整の影響を減らす。
- 手動の「名前編集開始」「Escによる取消し」マーカー。

手動マーカーは**ボタンを押した時刻**であり、Excel標準UIの編集開始やEscを自動検知した時刻ではない。Excel側は別フレームのため、このUIから編集状態やEscを確実に監視できるとは扱わない。編集開始は記録ボタンの直後、取消しはEsc後の記録となり、その時間差がある。マーカーを押すためのフォーカス移動自体が操作条件へ影響する可能性もある。

ブック内容・ブック名・シート名・シートID・URL・生エラー本文は診断JSONへ含めない。取得したID・名前は画面内メモリーにだけ保持し、Bの対象選択に使用する。エラーは安全なコード・API発生箇所などに限定する。結果JSONは外部へ自動送信しない。

## Excel for the webでの手順

### 起動と共通準備

1. SheetDockの既存開発環境でサーバーを起動する。証明書の新規インストールやマニフェスト再登録は今回の変更には不要。

   ```powershell
   Set-Location .\SheetDock  # Run from the parent of your checkout
   $env:PATH = "$PWD\.local-tools\node-v24.22.1-win-x64;" + $env:PATH
   npm.cmd run dev
   ```

2. 専用の検証ブックを開く。最初の比較は通常ワークシート3枚（例：Sheet1、Sheet2、Sheet3）にし、グラフシートや構成保護は別の条件として扱う。操作するタブは各試験で同じにする。
3. Excelのブラウザータブ全体を再読み込みし、SheetDockを表示する。「読み取り比較モードを開く（再読み込み）」を選ぶ。再読み込み後に比較専用画面であることを確認する。通常の一覧UIと既存PoCは同時に表示されない。
4. 画面のセッションを控える。各試験前に新しいセッションへ変わっていることを確認する。同じセッションで次の試験を続けない。

### 編集しない対照試験

A・B・Cを、それぞれ新しいページで1回ずつ実行する。実行中は名前編集をしない。Bだけは編集していない状態で「Bの対象を準備」を押し、完了後にSheet2など対象を選ぶ。

正常に返るか、run/sync回数と時間を保存する。ここで停止する試験は「名前編集との重なりで止まった」と分類しない。前提条件の失敗として保存する。

### 名前編集開始→Escとの重なり

各試験ごとに新しいページを用意する。Bは先に候補一覧取得を正常完了させ、Sheet2を選ぶ。Bの準備で停止した場合、本試験を開始しない。

1. A/B/Cの試験を選び、開始待ち時間を5秒にする。
2. 「読み取りを予約実行」を押す。予約後に試験種別や対象を変更しない。
3. カウントダウンが残り約1秒のところで編集開始の手動マーカーを押し、Excel標準タブのSheet2を名前編集モードにする。名前を書き換える必要はない。
4. 編集開始から約2秒後にEscで取り消す。取消し後にEscの手動マーカーを押す。
5. 「診断ログを表示・更新」を押し、「診断ログJSON」のテキストを全選択してコピー・保存する。DevToolsのフレーム選択やコンソールコマンドは不要。15秒警告が出た場合は、それ以降の別試験を同じページで実行しない。
6. 次の試験は新しいページで行う。APIが未応答の場合は、Excelのブラウザータブ全体を再読み込みする。

この操作はAPI要求と編集状態を重ねやすくする手順であり、必ず重なった保証ではない。人の操作時間差があるため、マーカーとAPI開始時刻が離れた試行は区別する。必要なら専用検証ブックの画面録画から編集開始・取消し時刻を補い、ボタン操作の記録と混同しない。

最初はA→B→C、再比較はC→A→Bなど順序を変える。各試験の間に新しいページを挟む。回数を増やす場合も、同一セッション内で連打しない。再現しない場合は「編集しない」「編集状態に重ねる」「Esc後に取得する」を別条件として記録する。

## Workbook.onActivatedの再登録調査

公式資料によると`Workbook.onActivated`は既に開いているブックへのフォーカス復帰を通知する。別ブックだけでなく、別アプリやExcel for the webの別ブラウザータブから戻った場合も対象で、新しくブックを開いたことを示す通知ではない。[Workbookのイベント](https://learn.microsoft.com/en-us/office/dev/add-ins/excel/excel-add-ins-workbooks#detect-workbook-activation)

`WorkbookActivatedEventArgs`は`type`のみを公開しており、接続先のブックIDを含まない（ExcelApi 1.13）。そのイベントだけで「同じブックへの復帰」と「接続対象の変更」を完全に識別できない。[イベント引数](https://learn.microsoft.com/en-us/javascript/api/excel/excel.workbookactivatedeventargs?view=excel-js-preview)

`Office.context.document.url`はURLが取得できない場合がある。既存コードのURL＋ブック名も、名前や保存先の変更・未保存状態を含めた恒久的なブックIDとは扱わない。比較値はメモリー内にとどめ、診断へ生URLを出さない。[Office.Document.url](https://learn.microsoft.com/en-us/javascript/api/office/office.document?view=common-js#office-office-document-url-member)

改善候補は、同一実行環境への単なる復帰では必要な状態の再取得にとどめ、実際の接続状態変化や登録失敗の証拠がある場合に再登録する方式。これは本調査時点の提案であり、全環境で安全に識別できることを確認済みとはしない。接続先が不明なら変更操作を許可せず、既存の操作直前照合を保つ。今回は本番用のイベント登録・解除を変更しない。

後続比較では、同じ検証ブックから別ブラウザータブへ移動して戻るケースと、別の検証ブックを別タブで開くケースを分ける。通常画面の診断session、初期化回数、workbookActivated回数、再登録回数を照合する。別ブックのタブにあるペインが別sessionなら、そのruntimeの新規初期化として扱う。この追加イベント観測をA/B/Cの最小試験へ混ぜない。

## 制約と未解決事項

- 名前編集UIへ入った瞬間やExcel側のEscを自動取得していない。手動マーカーには遅れとフォーカスの影響がある。
- 読み取り専用でも、APIが無応答になる可能性は調査対象として残る。ロックの強制解除や無制限再試行は行わない。
- 公式の`delayForCellEdit`はセル編集を説明する。既定falseは影響する処理を失敗させ、trueは編集の確定／取消しまで待機するという仕様である。シートタブ名の編集へ同一の保証がある、またはEsc後の長時間停止が正常仕様であるという根拠にはしない。[セル編集時の実行待機](https://learn.microsoft.com/en-us/office/dev/add-ins/excel/excel-add-ins-delay-in-cell-edit)
- 独立グラフシートや保護状態を含む比較は、この最小試験とは条件を分ける。Cの対象が通常ワークシートではない場合の失敗を、名前編集の停止と混同しない。
- 実機比較後に必要最小限の修正方針を決める。A/B/Cの結果が出る前にアクティブ表示を未検証キャッシュへ置き換えたり、通常同期を恒久停止したりしない。
