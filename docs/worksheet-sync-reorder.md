## 確認済みの範囲

ユーザー報告によるExcel for the webでの成功：一覧/切替、名前検索、イベント自動同期、Hidden/VeryHiddenの表示状態、PoCからのSheet2の先頭移動（Sheet1→Sheet2→Sheet3をSheet2→Sheet1→Sheet3へ）。

キャンセル、PoC結果表示、複数移動、構成保護は実機確認完了としていない。**今回の通常UI統合版、SHEETSによる混在判定、イベント再登録は実機未検証**。自動テストの成功と区別する。Windows Microsoft 365・Mac・複数ウィンドウも未検証。

## 通常画面の動作

- 起動時に自動同期を開始。ワークシートのアクティブ化/追加/削除/名前/位置/表示状態/シート保護の7イベントを購読。
- 手動更新は残す。フォーカス/表示復帰時も再取得する。
- 行の名前部分または左のドラッグハンドルから1シートを移動できる。非表示シートはハンドルから移動し、再表示/アクティブ化はしない。
- 行の上半分/下半分で挿入境界を決め、挿入線を表示する。末尾にはドロップ領域を設ける。
- 通常の移動に確認ダイアログや成功通知は出さない。Excelから再取得した順序・アクティブ状態を一覧に表示する。
- 同位置は書き込まない。Esc、ドラッグ終了、一覧外へのドロップは変更しない。別ペインや外部からのドラッグは受け付けない。
- 検索文字列がある間は、全件一致の場合も含めて移動を無効化。途中で検索条件や構成が変わったドラッグも破棄。
- 連続drop、移動中のドラッグ/シート切替/手動操作を抑止。移動失敗時はエラーと、取得できた現在状態を表示する。

## 安全性とSHEETSによる全種別の件数照合

以前のPoCでは、通常Worksheet一覧と連続したpositionだけでは末尾の独立グラフシート等を否定できなかった。今回は追加で`workbook.functions.sheets()`（ExcelApi 1.2）を引数なしで評価する。セルや数式の書き込みはしない。

MicrosoftのSHEETS仕様は、Visible/Hidden/VeryHiddenのワークシートに加え、グラフ/マクロ/ダイアログシートを含む総数を返す。通常Worksheet一覧の件数との一致と、位置の連続性・ID重複なしを併せて確認する。WorksheetCollection.getCountを全種類の総数の代わりには使用しない。

これは正式API仕様に基づく追加判定で、実機でのSHEETSの戻り値、特に混在ブックでの一致/不一致は今回未検証。取得失敗、関数エラー、不正な値、件数不一致、位置欠番の場合は混在を否定せず移動を無効にする。利用者の自己申告でこのガードを解除する機能は通常UIにない。

移動開始時のスナップショットを保持し、ドロップ後・書き込み直前に再取得して以下を確認する。

1. ブック識別情報（Office文書URLとブック名）とブック切替世代が一致。
2. readOnly=false、構成保護なし、アクティブシートを通常一覧で確認できる。
3. 全種別総数=通常シート数、positionが0から連続、ID重複なし。
4. 名前・ID・順序・表示状態・シート保護状態を含む構成が開始時と一致。
5. 対象が存在し、対象シートが保護されていない。シート保護は保守的に移動を拒否する。

単一移動の最終positionを計算し、対象だけへ1回書き込む。実行後、期待順序・その他の構成・アクティブIDを再取得して照合する。途中でAPIエラーが起きても変更済みの可能性を残し、自動ロールバックはしない。エラー時は改めて現在状態を取得する。再取得も失敗すれば一覧を消して手動更新を促す。

これらの読み取り/書き込みは原子的トランザクションではない。Excel標準UI・共同編集・別ウィンドウの操作を完全には排他できず、最終確認と書き込みの間の変更は残るリスク。URL/名前/シート情報も不変のグローバルIDではない。永久的なIDだけに依存して安全と判断しない。

## 自動同期・ブック切替・復旧

通常UIとPoCはSharedEventsで1つの登録を共有する。両方が有効でも7イベントとWorkbook.onActivatedの合計8ハンドラを1セットだけ登録し、最後の利用者が終了したときに同じRequestContextで解除する。PoCの観測スイッチをOFFにしても通常UIの同期は継続する。

Requirement Setは、ワークシートのアクティブ化/追加/削除1.7、名前/位置/表示状態1.17、シート保護1.14、Workbook.onActivatedは1.13。マニフェストの1.17は変更していない。

150msの窓で更新要求を集約。取得中のイベントは後続1回へ持ち越す。Excel APIの実行は既存のキューで直列化する。現在のブック観測はメタデータ・アクティブ・SHEETSを分けた3 syncで、セルデータは読まない。大量シートでの性能は未評価。PoCの観測を同時ONにすると、その観測用取得は別に加わる。

Workbook.onActivatedの発火時はドラッグの世代を更新して古い一覧/ドラッグを無効にし、旧イベントの解除→再登録→再取得を行う。取得中にブック世代が変化した場合は古い取得結果を表示しない。フォーカス復帰で文書URL/ブック名の変化を検出した場合も再登録する。

Office Web Add-inのペインは基本的に文書ごとのランタイムであり、Excelプロセス内の全ブックを監視するVSTO方式ではない。Webの別ブック/別タブではそのブックのペインを開いて利用する。閉じたランタイムのハンドラを新しいブックへ持ち越す設計にはしていない。Workbook.onActivatedは開いた瞬間には発火しないため、初回の登録・取得を別途行う。

登録失敗後にハンドラを解除できた場合は、次のイベント取得/フォーカス復帰/手動更新で再試行する。解除できず登録状態が不明な場合は二重登録を避けて再登録を禁止し、ペインの開き直しを案内する。取得の一時エラーは次の成功で解消する。操作失敗のメッセージは自動取得によって勝手に成功通知へ置き換えない。

ブック構成保護・readOnlyの専用変更イベントを前提としない。フォーカス復帰/手動更新と移動直前の再検証で確認する。共同編集のイベント到達・順序を完全保証しない。

## PoCとの分離

既存のPoC、確認ダイアログ、複数移動/状態変更/削除等の実験処理は残す。共有するのはイベント登録・直列化・移動計算等の汎用部分。通常UIはsrc/pocをimportしない。

productionには通常UIの同期と単一移動を含めるが、src/poc、PoC Dialog、SyntheticFailure、複数操作エンジンを含めない。webpackのモジュール一覧と成果物で確認する。
